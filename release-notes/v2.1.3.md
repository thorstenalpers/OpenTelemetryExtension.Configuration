# v2.1.3

_Released: 2026-07-29_

## Changed
- Updated all bundled OpenTelemetry packages to 1.17.0
  (`Exporter.OpenTelemetryProtocol`, `Extensions.Hosting`, `Instrumentation.Http`,
  `Instrumentation.AspNetCore`, `Instrumentation.Runtime`). No public API or
  runtime behavior change.
- `OpenTelemetry.Instrumentation.Runtime` now moves with the other packages. It
  was left behind on 1.15.1 in v2.1.2, whose notes already claimed the whole set
  had reached 1.16.0.
- Updated the sample and test project dependencies (EF Core, ASP.NET Core OpenAPI,
  Swashbuckle, NLog, `Microsoft.Data.SqlClient`, test SDK). These are not part of
  the shipped package.

## Fixed
- README stated that ASP.NET Core instrumentation was `net10.0` only. It ships in
  the `net8.0` build as well — corrected in the requirements, the configuration
  reference and the section on running outside the Generic Host.
- The database instrumentation section referenced `OpenTelemetry.Instrumentation.Npgsql`
  and `AddNpgsql()`, which do not exist — Npgsql is wired up through its
  `ActivitySource`. The MySQL example pointed at the unmaintained `MySqlData`
  package.
- The same section assigned `ConfigureTracing` four times in a row, so every line
  silently discarded the previous one. It is a single delegate and is now shown
  as one chained assignment.
- `HttpClient` and the .NET runtime were described as built-in alongside SQL,
  which is not instrumented out of the box.

## Added
- README: table of contents, a per-target requirements matrix, and an explanation
  of how `Endpoint` and `Protocol` interact — including that the per-signal path
  is appended for `HttpProtobuf` but not for `Grpc`, and that `Enabled: false`
  skips validation so no endpoint is needed.
- README: the local backend table now also lists SigNoz, Grafana/Loki and
  OpenSearch, which already had launch profiles and install scripts.
